# UI/UX 설계 문서

**결론: 이 앱은 "기능을 다 보여주는 앱"이 아니라 "내 기기 상태를 한눈에 보고 바로 조작하는 앱"으로 설계합니다.** 화면에 뭘 넣을지 고민될 때마다 아래 우선순위를 기준으로 판단합니다.

> **정보 우선순위: 기기 상태 > 주요 제어 > 기기 관리 > 부가 콘텐츠(공지/이벤트/CS 등)**

이 문서는 ChatGPT로 검토받은 요구사항(사용자가 공유해주신 피드백)을 참고해서, 이 프로젝트에 실제로 적용할 화면 구조를 정리한 것입니다. 지난 대화에서 제가 먼저 제안했던 하단 탭 구성(홈/케어기록/상담/마이 4개)은 이 문서에서 **3개(홈/기기/설정)로 다시 조정**했습니다. 이유는 2번 항목에 설명했습니다.

## 0. 설계 원칙

**결론: 사용자(기획자)가 요청한 화면 구성이라도, UX 관점에서 더 나은 방법이 있다고 판단되면 그대로 따르지 않고 대안을 제안합니다.** 요구사항 문서에 적힌 내용을 그대로 화면에 옮기는 게 목표가 아니라, 실제로 써봤을 때 편한 앱을 만드는 게 목표이기 때문입니다.

예를 들어 아래와 같은 상황에서는 원래 요청과 다르게 판단할 수 있습니다.

| 상황 | 판단 방식 |
|---|---|
| 요청받은 정보가 너무 많다 | 우선순위를 매겨서 일부는 다른 화면으로 미루거나 축약 |
| 카드가 너무 많아진다 | 비슷한 성격의 정보를 하나로 합치거나, 목록에서는 요약만 보여주고 상세는 별도 화면으로 분리 |
| 특정 UI 패턴이 조작하기 불편하다 | 다른 패턴(예: 세로 나열 대신 가로 칩, 모달 대신 풀스크린)으로 대체 제안 |
| 요청에 없던 예외 상황(빈 상태, 연결 끊김, 검색 실패 등)이 빠져 있다 | 실제 사용 시나리오를 고려해 먼저 짚어서 보완 제안 |

이 문서의 이후 내용도 전달받은 요구사항을 그대로 옮긴 게 아니라, 위 기준으로 한 번 걸러서 정리한 결과입니다 (예: 2번 항목의 하단 탭 개수 조정).

### 새 화면을 만들 때 체크리스트

**결론: 화면을 다 만든 뒤에는 "예쁜가?"가 아니라 아래 5가지를 먼저 확인합니다.**

1. 이 화면이 Deepth Smart 대시보드와 같은 제품의 화면처럼 보이는가? (크림 배경/네이비 텍스트/오렌지 CTA 톤이 유지되는가)
2. 사용자가 가장 중요한 정보를 1~2초 안에 이해할 수 있는가?
3. 가장 중요한 행동(주요 CTA)이 명확히 하나로 정해져 있는가?
4. 불필요한 정보나 카드가 없는가?
5. 모바일에서 실제로 손으로 쓰기 편한가? (터치 영역, 여백)

## 1. 이번 작업 범위

| 구분 | 내용 |
|---|---|
| 이번에 만드는 것 | 사용자용 App의 대시보드(홈), 디바이스 관리, 기기 등록 흐름의 기본 구조 |
| 나중에 확장할 것 | 기기 상세 제어(A2/A3), OTA 업데이트 화면, 공지사항, 이벤트, FAQ, 1:1 CS, 설정, 언어 변경 |
| 이번에 안 만드는 것 | 관리자(Admin) 웹/백오피스 화면 전체 |

## 2. 하단 네비게이션 — 3개 탭으로 축소

**결론: 홈 / 기기 / 설정, 이렇게 3개 탭으로 시작합니다.**

| 탭 | 화면 | 왜 이렇게 정했나 |
|---|---|---|
| 홈 | 대시보드 | 앱을 켰을 때 가장 먼저 봐야 하는 "내 기기 상태" 화면 |
| 기기 | 디바이스 관리 | 요구사항에서 대시보드 다음으로 2순위로 명시된 화면이라, "마이" 같은 하위 메뉴에 숨기지 않고 탭으로 바로 노출 |
| 설정 | 프로필/언어/공지사항/CS 등 진입점 | 지금 당장 만들 화면은 아니지만, 나중에 공지사항·CS·언어변경·회원정보 화면이 생기면 들어갈 자리를 미리 확보 |

**지난 제안과 달라진 점**: 이전에는 "챌린지"(연속 사용일 기록)를 위한 탭을 따로 뒀는데, 이번에 참고한 요구사항의 "이후 확장될 화면" 목록에 챌린지가 아예 없어서, 지금 단계에서는 탭에서 빼고 나중에 필요해지면 홈 화면 안에 작은 카드로만 넣는 걸로 방향을 바꿨습니다. 마찬가지로 CS(1:1 상담)도 "이후 확장" 항목이라 탭이 아니라 "설정" 안에 넣는 진입점 정도로만 자리를 잡아둡니다.

## 3. 대시보드(홈) 화면

**결론: 화면을 열자마자 "내 기기가 지금 어떤 상태인지"가 스크롤 없이 바로 보여야 합니다.**

### 정보 우선순위 (위에서 아래 순서)

| 순서 | 영역 | 보여줄 내용 |
|---|---|---|
| 1 | 현재 기기 카드 | 기기 이미지, 기기 이름(A2/A3 등), 연결 상태, 배터리, [기기 제어] 버튼 |
| 2 | 현재 상태 요약 | 온도 / 강도 / 모드 / 작동시간 |
| 3 | 빠른 기능 | 기기관리 바로가기, 최근 사용 모드 바로 실행 |
| 4 | 추천/최근 모드 | 최근에 많이 쓴 모드 카드 |
| 5 | 내 기기 요약 | "등록된 기기 2개" 같은 한 줄 요약 (탭하면 "기기" 탭으로 이동) |
| 6 | 공지/이벤트 | 카드 또는 배너 (다국어 고려, 아래 6번 참고) |

### 레이아웃 스케치

```
┌─────────────────────────────┐
│ Deepth Smart      🌐 🔔 👤   │  ← 언어 / 알림 / 프로필
├─────────────────────────────┤
│ [A2 ▾] [A3]                 │  ← 기기 2개 이상일 때만 노출되는 전환 칩
│ ┌───────────────────────┐   │
│ │      제품 이미지        │   │
│ │  ●연결됨    배터리 82%  │   │
│ │      [ 기기 제어 ]      │   │
│ └───────────────────────┘   │
│ 온도 43℃ · 강도 중 · 순환모드 │
│ 남은시간 12분                │
├─────────────────────────────┤
│ [기기관리]     [최근사용]     │
├─────────────────────────────┤
│ 추천 모드  →                 │
│ [순환]  [수면]  [파워]       │
├─────────────────────────────┤
│ 내 기기 2개 관리하기 →        │
├─────────────────────────────┤
│ 공지 · 이벤트 배너            │
├─────────────────────────────┤
│  홈 |  기기  |  설정          │
└─────────────────────────────┘
```

### 기기가 여러 개일 때

기기가 1개면 상단 전환 칩을 아예 숨겨서 화면을 더 단순하게 유지합니다. 2개 이상일 때만 칩이 나타나고, 칩을 누르면 카드 내용 전체(이미지·상태·현재 설정)가 선택한 기기 것으로 바뀝니다. 즉 "여러 기기를 동시에 나열"하지 않고 "하나씩 전환해서 보는" 방식이라 화면이 복잡해지지 않습니다.

### 연결 안 됨 / 오류 상태

| 상태 | 화면에 보여줄 것 |
|---|---|
| 정상 연결됨 | 초록색 점 + "연결됨" |
| 연결 끊김 | 회색 점 + "연결 안 됨" + [다시 연결] 버튼 |
| 등록된 기기가 0개 | 카드 대신 "아직 등록된 기기가 없어요" 안내 + [기기 등록하기] 버튼 |

## 4. 디바이스 관리 화면

**결론: 등록된 기기들을 카드로 나열하고, 각 카드만 봐도 "이 기기가 지금 괜찮은지"를 바로 판단할 수 있어야 합니다.**

### 기기 카드에 보여줄 정보

| 항목 | 예시 |
|---|---|
| 제품명 / 모델명(SKU) | Deepth A2 |
| 연결 상태 | ● 연결됨 / ○ 연결 안 됨 |
| 최근 사용 일시 | 오늘 09:30 |
| 펌웨어 버전 | v1.2.0 (최신) 또는 "업데이트 필요" 배지 |
| 진입 버튼 | [관리 >] |

### 레이아웃 스케치

```
┌─────────────────────────────┐
│ ← 기기                       │
├─────────────────────────────┤
│ ┌───────────────────────┐   │
│ │ 이미지  Deepth A2       │   │
│ │        ●연결됨          │   │
│ │  최근 사용: 오늘 09:30   │   │
│ │  펌웨어 v1.2.0 · 최신    │   │
│ │                [관리>]  │   │
│ └───────────────────────┘   │
│ ┌───────────────────────┐   │
│ │ 이미지  Deepth A3       │   │
│ │        ○연결 안 됨      │   │
│ │  최근 사용: 어제 21:10   │   │
│ │  ⚠ 업데이트 필요  [업데이트]│   │
│ │                [관리>]  │   │
│ └───────────────────────┘   │
│      [ + 새로운 기기 등록 ]   │
└─────────────────────────────┘
```

**OTA(펌웨어 업데이트) 노출 원칙**: 최신 버전이면 회색 글씨로 조용히 "v1.2.0 · 최신"이라고만 표시하고, 업데이트가 필요할 때만 눈에 띄는 배지와 버튼을 보여줍니다. 이렇게 하면 평소에는 화면이 "업데이트 관리 화면"처럼 보이지 않습니다.

## 5. 기기 등록 흐름

**결론: 검색이 실패하거나 오래 걸려도 사용자가 다음에 뭘 해야 할지 항상 화면에 나와 있어야 합니다.** (기존 고객 문의 중 블루투스 연결/기기 등록 문제 비중이 컸다는 점을 반영)

```
디바이스 관리 → [+ 기기 등록] → 주변 기기 검색 → 검색 결과 → 기기 선택
→ 연결 중 → 기기 정보 확인(별칭 설정 가능) → 등록 완료
```

| 상황 | 화면에 보여줄 것 |
|---|---|
| 검색 중 | 검색 애니메이션 + "블루투스가 켜져 있는지 확인해주세요" 안내를 상시 노출 |
| 기기를 찾음 | 발견된 기기 리스트 (여러 개 나올 수 있음, 실시간으로 추가) |
| 못 찾음 | "다시 검색" 버튼 + "기기 전원이 켜져 있나요? 기기와 가까이 있나요?" 같은 해결 가이드 |
| 등록 완료 | 체크 아이콘 + [기기 제어로 이동] 버튼 |

## 6. Multi-SKU(여러 기기 종류) 확장 원칙

**결론: 화면 코드에 "A2"를 직접 박아넣지 않고, 기기 종류별 정보를 데이터로 분리해서 화면이 그 데이터를 보고 알아서 다르게 그려지도록 만듭니다.**

예를 들어 A2(눈마사지기)는 온도/강도/모드/시간을 조절하지만, 향후 나올 다른 기기는 조절 항목이 다를 수 있습니다. 그래서 "이 기기 종류는 어떤 항목을 조절할 수 있는가"를 기기 프로필 데이터로 관리하고, 기기 상세 화면은 그 데이터를 읽어서 항목을 하나씩 그려주는 방식으로 만듭니다. 이렇게 하면 새 기기가 추가돼도 화면 코드를 새로 짤 필요 없이 데이터만 추가하면 됩니다.

## 7. 다국어 대응 원칙

**결론: 한국어 글자 수 기준으로 버튼/카드 크기를 고정하지 않습니다.**

| 피해야 할 것 | 대신 이렇게 |
|---|---|
| 버튼 너비를 글자 수에 맞춰 고정 | 버튼 안 여백만 정하고, 너비는 텍스트 길이에 따라 자동으로 늘어나게 |
| 카드 안 문장을 한 줄로 고정 | 두 줄까지 허용하고, 넘치면 "..."으로 줄임 |
| 아이콘 없이 텍스트만 사용 | 짧은 아이콘 + 텍스트 조합으로, 영어로 바뀌어 길어져도 의미가 통하게 |

## 8. 디자인 톤

| 원하는 방향 | 피해야 하는 방향 |
|---|---|
| 깔끔하고 여백이 넉넉함 | 화면 하나에 정보를 다 욱여넣기 |
| 큰 글씨, 큰 버튼(터치하기 쉬움) | 작은 글씨, 작은 버튼 |
| 상태를 색/아이콘으로 직관적으로 표현 | 숫자와 표로 나열하는 관리자 대시보드 느낌 |
| 포인트 컬러 1~2개로 절제 | 장식이 많고 실제 사용성은 떨어지는 디자인 |

### 레퍼런스 이미지 기반 구체적인 값

`assets/references/image1.png`(AI로 생성한 대시보드·디바이스 관리 무드보드)를 보고 정한 값입니다. 정확한 색상 코드가 아니라 "이 톤 계열로 간다"는 방향입니다.

| 항목 | 값 |
|---|---|
| 메인 포인트 컬러 (모든 주요 CTA 버튼에 공통 사용) | 따뜻한 앰버/오렌지 (등록·주요 액션 버튼, 활성 탭, 이벤트 태그) |
| 보조 컬러 (버튼에는 쓰지 않음, 텍스트/제목 전용) | 딥 네이비 |
| 배경 | 크림/아이보리 계열의 따뜻한 무채색 (순수 흰색보다 따뜻한 톤) |
| 카드 | 큰 radius(20px 이상), 은은한 그림자, 넉넉한 내부 여백 |
| 아이콘 | 라인 아이콘 + 항목별로 다른 파스텔 원형 배지(모드 카드 등) |
| 카피 톤 | "오늘도 눈에 휴식을 선물하세요", "안녕하세요, OO님"처럼 다정하고 딱딱하지 않은 문구 |

**주의**: 이 레퍼런스에서는 A2/A3 둘 다 "Eye Massager"로 표기돼 있는데, 실제로는 제품마다 카테고리가 다를 수 있으므로(6번 항목 Multi-SKU 원칙) 화면 코드에 카테고리명을 고정하지 않고 기기 데이터에서 가져오게 합니다.

### 최종 색상 코드 (global.css에 반영 완료)

**결론: 위 표는 "어떤 톤인지"에 대한 방향이었고, 아래는 최종 확정된 레퍼런스(`image2.png`, `image3.png`)에서 실제 픽셀 값을 추출한 정확한 색상 코드입니다.** `global.css`, `tailwind.config.js`에 이미 반영해뒀습니다.

| 용도 | 색상 | 설명 |
|---|---|---|
| 배경 | `#fcf6f0` | 전체 화면 배경 (크림) |
| 카드 배경 | `#f6f0ea` | 기기 상태 카드 등 |
| 메인 액션(주요 버튼) | `#f6a512` | "테라피 시작하기" 같은 핵심 CTA |

다크 모드용 색상은 아직 검증된 레퍼런스가 없어서, 같은 웜톤 계열로 추정해 1차 초안만 넣어뒀습니다 — 실제로 다크 모드를 만들 때 다시 검토가 필요합니다.

### 레퍼런스 검토 후 발견한 문제

| 문제 | 내용 |
